# Отчёт о проверках MikuOS

## Доводка движений после визуального замечания

Уменьшены амплитуды рук и покачивания ног; приветствие переделано в IK-позу
с согнутым локтем рядом с головой. Think больше не перекрывает лицо так сильно.
Run/Chase используют ту же опорную IK-траекторию, что Walk; их частота согласована
с ускорением перемещения 1,6×. Скорости стопы на границах опоры/переноса согласованы,
подъём стопы имеет нулевую вертикальную скорость при касании.
Высота посадки теперь смешивается синхронно с позой, без дополнительного запаздывания.
Поворот корпуса к курсору имеет мёртвую зону 25 px. Исправлена потеря длительности
статических клипов при оптимизации константных каналов.

Модель пересобрана. Просмотрены пять фаз шести движений непосредственно в Qt:
`data/validation/motion-phases.png`; генератор — `tools/preview_motion_phases.py`.
Повторная проверка `test_character_animation.py` + `test_overlay.py`: **15 passed**,
25,93 с. Ранее описанное сообщение Windows 0xc0000139 всё ещё выводится при
создании QWebSocket, тесты завершаются успешно. Полного устранения пересечений
одежды и production-качества всех движений эта доводка не подтверждает.

## Последняя проверка системы анимации — 24.10.2026

Этот раздел относится к новой реализации; исторические результаты ниже не заменяют

Проверены видимость модели, стоячие/сидячие позы, руки, прыжок, эмоции через доступные morphs.
Первоначально Think выглядел как вытянутая рука; исправлен на запечённую IK-позу у лица
и повторно просмотрен. Это выборочная проверка кадров, не гарантия качества каждого кадра.

### Ограничения среды и незавершённые функции

- Только один физический монитор 100% DPI. Mixed-DPI требует преобразований координат
  и реальной проверки; поддержка нескольких виртуальных прямоугольников этого не доказывает.
- При создании Qt QWebSocket pytest/faulthandler иногда печатает Windows exception
  `0xc0000139`; процесс продолжает работу, проверки сети заканчиваются успешно.
  Причина системного сообщения не установлена, оно не скрыто. В sandbox также были
  ограничения tempfile, hotkey и зависание TestClient; полноценные интеграции выполнены вне sandbox.
- Волосы имеют ограниченные пружины, но не capsule/mesh collisions; возможны пересечения.
- Run/Jump требуют дополнительной анимационной доводки; полной фиксации стоп при
  crossfade/поворотах и отдельного контактного отталкивания нет.
- Реальный TTS/RVC/audio output отсутствует: проверен интерфейс RMS и закрытие рта,
  не акустическая синхронизация. Фонемы и речевые жесты пока не реализованы.
- GPU timestamp/VRAM процесса, многошаговая маршрутизация и подтверждение завершения команд
  не реализованы. Полный список и контракт интеграции: ANIMATION_SYSTEM.md.

## 3. Непроверенные компоненты

- **Физическое нажатие** аварийной горячей клавиши с клавиатуры.
- **Реальные клики мышью по персонажу**: клик, двойной клик (чат), перетаскивание, контекстное меню, клики «сквозь» прозрачную часть. Код есть, но синтетический ввод здесь недоступен.
- Окно настроек, диалог памяти и меню трея — не тестировались автоматически.
- **Несколько мониторов и масштаб ≠ 100 %**: доступен только один монитор 96 DPI. Отрицательные координаты проверены перемещением окна и юнит-тестом поверхностей.
- Подавление в **настоящей полноэкранной игре/презентации**: логика проверена с подменой; функция детекта вызывалась, но реальная игра не запускалась.
- Реальный сдвиг курсора (`cursor_control=allow`) — выключен по умолчанию, не запускался.
- Автозагрузка модели скриптом (`lms load`), когда ни одна модель не загружена — модель уже была загружена.
- Длительная работа (часы), автоматическое закрытие разговора через 30 минут тишины в реальном времени.
- Режим `tool_mode=json_fallback` с настоящей моделью (нативные tool calls у этой Gemma работают, fallback проверен только на mock).
- Сценарий `-Cli` скрипта запуска (интерактивный) и `-BackendOnly`.

## 4. Известные ограничения и ошибки

1. **Нестабильный live-тест окна чата**: иногда ответ не приходит за 60 с. Причина не установлена (подозрение — параллельные запросы к LM Studio от второй работающей копии MikuOS или блокировка генерации). Расследование не завершено.
2. **Модель 4B иногда ошибается в использовании инструментов**: описывает вызов словами (смягчено ≤2 служебными подсказками), вызывает не тот инструмент (например, `read_window_elements` вместо чтения файла), выбирает странное «активное окно» при запуске из терминала.
3. **Устаревшие данные из истории**: после запрета `observe_metadata` модель может повторить старые координаты окна из предыдущей реплики, выдавая их за текущие.
4. **«Мы снова разговариваем»**: дообученная модель склонна говорить «снова», даже когда истории нет. Для явных выдумок («помню наш разговор о нотах») добавлен якорь в контекст — после него выдуманные воспоминания в тестах не повторялись, но гарантии нет.
5. Проверка честности ловит явные глаголы прошедшего и настоящего времени и «отправила/отправляю команду (запрос)»; другие формулировки могут проскочить.
6. `Ctrl+Alt+M` на тестовой машине занят другой программой → используются `Ctrl+Alt+Shift+M` / `Ctrl+Alt+F12` (backend и overlay берут разные). Фактическое сочетание — в меню и в `/api/status`.
7. Тайм-аут инструмента не может прервать уже начатый вызов WinAPI в потоке — результат просто отбрасывается.
8. FTS5 со стеммингом по префиксу — грубый: возможны промахи и лишние совпадения; эмбеддинги не подключены (интерфейс есть).
9. Не реализовано: OCR. Голос (STT/TTS) и голос Мику через Applio (RVC) — см. разделы ниже.
10. 3D-аватар: анимации процедурные и простые (без физики волос и юбки, без IK — ступни при ходьбе
    могут слегка скользить); при сидении на «полу» (панель задач) ноги свисают поверх панели.
