Реальный запуск без backend: **30,3 FPS**, около **255 МБ RAM**. Полные коллизии волос,

Локальный AI-компаньон для Windows 11: Хацунэ Мику живёт на рабочем столе, общается через уже
установленную в LM Studio модель (Gemma 4 E4B, дообученная под Мику), помнит разговоры в SQLite и
по вашей просьбе выполняет разрешённые действия в Windows.

Всё работает локально: backend слушает только `127.0.0.1`, модель — в LM Studio, память — в
`data/mikuos.db`.

## Требования

**Полная инструкция со всеми нужными программами — [SETUP.md](SETUP.md).**

- Windows 10/11 x64.
- LM Studio с загруженной моделью (автор использует Gemma 4 E4B, дообученную под Мику; подойдёт
  любая модель с поддержкой tool calling).
  Скрипт запуска сам включит сервер LM Studio (`lms server start`) и загрузит модель с `miku` в имени,
  если ни одна не загружена. Другие модели не скачиваются.
- [uv](https://docs.astral.sh/uv/) или Python 3.12. Проект использует собственное окружение `.venv`
  (Python 3.12) и не зависит от системного Python.

## Установка

```bash
powershell -ExecutionPolicy Bypass -File run_mikuos.ps1 -Install
```

Скрипт создаёт `.venv` (Python 3.12) и ставит зависимости из `requirements.txt`
(FastAPI, uvicorn, httpx, PySide6, pywin32, comtypes, jsonschema, psutil, pytest).

## Запуск

**Ярлык «MikuOS» на рабочем столе** (создаётся командой `.\run_mikuos.bat -Shortcut`) или:

```bash
.\run_mikuos.bat
```

Один этот файл сам: создаёт окружение при первом запуске, включает сервер LM Studio и загружает
модель Мику, собирает 3D-модель из Blender-сцены (если ещё не собрана), запускает backend и персонажа.

- по умолчанию: персонаж на рабочем столе + backend (стартует автоматически); значок в трее;
- `.\run_mikuos.bat -Cli` — чат в терминале (backend в фоне);
- `.\run_mikuos.bat -BackendOnly` — только backend в текущей консоли;
- `.\run_mikuos.bat -Test` — все автотесты (live-тесты выполняются, если LM Studio запущен).

### Управление персонажем

- **Двойной клик** по Мику — окно чата. **Клик** — реакция (и, если позволяет режим, реплика).
- **Перетаскивание** — переносит Мику; отпустите — она упадёт на ближайшую поверхность.
- **Правый клик / значок в трее** — меню: чат, настройки, режим инициативности, наблюдение,
  сон, аварийная остановка, выход.
- Точка у головы: 🟢 LM Studio подключена, 🟡 LM Studio недоступна, 🔴 backend не запущен,
  🟣 аварийная остановка. «Глаз» — наблюдение за активностью включено (видимый индикатор).
- В полноэкранных играх и презентациях Мику скрывается и не заговаривает.

### Аварийная остановка

`Ctrl+Alt+M` отключает все инструменты, наблюдение, инициативу и управление курсором; персонаж
становится полностью «прозрачным» для мыши. Снять — пункт меню «Снять аварийную остановку».

> Если `Ctrl+Alt+M` уже занят другой программой (Windows вернёт
> `ERROR_HOTKEY_ALREADY_REGISTERED`), MikuOS регистрирует запасные сочетания
> `Ctrl+Alt+Shift+M` и `Ctrl+Alt+F12` (backend и overlay берут по одному). Фактическое сочетание
> показано в меню и в `GET /api/status` → `hotkey.active`. Список запасных — `hotkey.fallbacks`.

### Чат в терминале

Команды: `/status`, `/memory`, `/forget <id>`, `/pending`, `/approve <id>`, `/deny <id>`,
`/mode chatty|normal|quiet|dnd`, `/new`, `/stop`, `/resume`, `/quit`.

## Настройки

Все параметры — в `config/settings.json` (создаётся при первом запуске; правится вручную или в
окне «Настройки»). Переменные окружения из `.env` (см. `.env.example`) имеют приоритет.

| Раздел | Что настраивает |
|---|---|
| `lmstudio` | endpoint, `model` (`auto` или id), предпочтение по имени, `reasoning_effort` (по умолчанию `none` — отключает «размышления» Gemma 4, иначе они съедают лимит токенов), `tool_mode` (`native`/`json_fallback`/`auto`), тайм-ауты и повторы |
| `generation` | temperature, top_p, max_tokens, длина контекста (0 = как загружено в LM Studio) |
| `paths` | БД, бэкапы, системный промпт, правила среды, лор |
| `memory` | авто-запоминание, подтверждение чувствительных фактов, сколько памяти и сообщений класть в контекст, порог дубликатов, суммаризация |
| `initiative` | режим, cooldown по режимам, дневной лимит обращений к LLM, пороги отсутствия/долгой работы |
| `observation` | включение, частота опроса, хранить ли заголовки окон |
| `permissions` | для каждого класса действий: `allow` / `ask` / `deny` |
| `allowed_apps` | id → исполняемый файл (модель может открыть только эти) |
| `allowed_directories` | папки для чтения и записи (по умолчанию `data/sandbox` и `~/Documents/MikuOS`) |
| `content_allowed_processes` | процессы, чьё содержимое окна можно читать (по умолчанию `notepad.exe`) |
| `agent` | лимит итераций инструментов, бюджет ошибок, окно защиты от повторов |
| `server` | порт (хост всегда localhost) |
| `ui`, `hotkey`, `logging` | интерфейс, горячие клавиши, логи |

Разрешения по умолчанию: метаданные окон, открытие приложений и управление окнами, чтение файлов —
разрешены; запись файлов, чтение содержимого окон и нажатие элементов UI — **с подтверждением**;
управление курсором — **запрещено** (включается в настройках с отдельным согласием).

**Всё, что удаляет данные, всегда ждёт вашего подтверждения** (класс `destructive`): удаление игры
Steam и перезапись существующего файла. Значение `allow` для этого класса игнорируется — можно
выбрать только `ask` или `deny`. Самостоятельные реплики Мику (инициатива) не могут даже запросить
такое действие. Удаление игры дополнительно подтверждается в собственном окне Steam.

### Steam

Steam находится автоматически (реестр). Мику может: показать установленные игры
(`list_steam_games`, из файлов библиотеки Steam), открыть Steam (`open_application` → `steam`),
запустить игру (`launch_steam_game`, через `steam.exe -applaunch <id>`; Мику сообщает, появился ли
процесс игры), удалить игру (`uninstall_steam_game` — только после подтверждения).

### Браузер и Spotify

- `open_website` / `web_search` (класс `web`, по умолчанию разрешено) открывают страницу в браузере
  по умолчанию. Только `http`/`https` и публичные сайты: ссылки на `localhost`, IP-адреса,
  `.local`/`.lan`, с логином-паролем внутри, `file:`, `javascript:` и т. п. отклоняются. Мику не
  видит открытую страницу и не пересказывает её. Поисковик — `web.search_url` (`{q}` — запрос).
- Spotify (класс `media`): `spotify_now_playing` — по заголовку окна Spotify; `spotify_control` —
  `pause` / `play` / `next` / `previous` через `WM_APPCOMMAND` только окну Spotify (без эмуляции
  клавиатуры); `spotify_play` находит трек по названию и исполнителю и включает первый результат поиска (кнопка «Слушать» в результатах через UI Automation, только в окне Spotify; если этот трек уже играет — ничего не нажимается); `spotify_search` только открывает поиск; `open_spotify`.
  Вход в аккаунт и Web API не нужны.
- Как и для других действий: после чтения чужого текста (названия треков, файлы, окна) открытие
  сайтов требует подтверждения; самостоятельные реплики Мику ничего не открывают.

### Голос

- **Сказать Мику голосом:** кнопка 🎤 в окне чата, пункт меню «🎤 Сказать голосом» или горячая
  клавиша `Ctrl+Alt+Space` (если она занята другой программой — запасная `Ctrl+Alt+V`; фактическая
  показана в меню). Нажали → у Мику красный значок микрофона и облачко «Слушаю…» → говорите →
  после паузы ~1,2 с запись заканчивается сама (или нажмите ещё раз). Фраза появляется в чате
  «Ты 🎤», ответ Мику — в чате и вслух.
- **Приватность:** микрофон включается только вашим нажатием и выключается после фразы; сама Мику
  (модель) включить его не может — такого инструмента нет; звук нигде не сохраняется, в истории
  остаётся только распознанный текст. Аварийная остановка сразу закрывает микрофон и обрывает речь.
- Мику озвучивает и ответы в чате, и свои реплики: `voice.speak_replies` = `all` | `voice` (только
  голосовые разговоры) | `off`; `voice.speak_initiative`. Повторное нажатие во время речи её прерывает.
- Распознавание: faster-whisper `small` на процессоре (`voice.stt_model`: `tiny`…`medium`), язык
  `voice.language`. Синтез: Silero `v4_ru`, голос `voice.tts_speaker` (`xenia`, `baya`, `kseniya`,
  `aidar`, `eugene`). Модели (~0,5 ГБ и 40 МБ) скачиваются один раз в `data/models/` и загружаются
  при запуске (`voice.preload`). Латиница читается приблизительно, числа — словами.
- Зависимости: `requirements-voice.txt` + `torch` (CPU) — ставит `run_mikuos.bat -Install`. Без них
  MikuOS работает как раньше, просто без голоса. Модели Silero — для некоммерческого использования.
- **Голос Мику через Applio (RVC):** если установлен [Applio](https://applio.org) (`%LOCALAPPDATA%\Applio`)
  и в нём есть модель с `miku` в имени, каждая фраза Silero перед воспроизведением проходит через эту
  модель (Python и видеокарта Applio, фоновый процесс `mikuos/voice/applio_worker.py`; окно Applio
  открывать не нужно). Параметры берутся из пресета модели в Applio; настройки — `voice.rvc`.
  Любая ошибка → обычный голос Silero. Подробно — [SETUP.md](SETUP.md#24-applio--голос-мику-rvc).

## 2D-спрайты Мику (по умолчанию)

Положите в `assets/sprites/` два файла: `miku_sheet.png` — лист спрайтов на однотонном фоне и
`miku_idle.gif` — анимацию ожидания (прозрачный GIF). При первом запуске лист нарезается на кадры
автоматически (кадры = связные области не-фонового цвета, кэш — `assets/sprites/frames.json`), фон
становится прозрачным, при ходьбе влево кадры зеркалятся. Какие кадры к каким движениям — таблица
`ANIMS` в `mikuos_client/sprite_renderer.py` (номера кадров — по строкам листа слева направо).
Пиксели масштабируются без размытия: `ui.sprite_scale` (по умолчанию 2). Выбор аватара —
`ui.avatar`: `auto` (спрайты → 3D → векторная заглушка) | `sprite` | `3d` | `placeholder`.

### Шутка с курсором

Если включить в «Настройках» галочку «Разрешить Мику хватать курсор и убегать с ним» (класс
разрешения `cursor_control`, по умолчанию **выключен**, включение подтверждается отдельным
окном), Мику, поймав курсор во время игры с ним, иногда хватает его и убегает на 2–3 секунды.
Резко дёрните мышь — курсор вырвется (Мику обидится). Она не трогает курсор, пока зажата кнопка
мыши, в полноэкранных приложениях, без backend и при аварийной остановке; не чаще раза в
`ui.cursor_prank_cooldown_s` (120 с), с вероятностью `ui.cursor_prank_chance` (0,5) за поимку;
`ui.cursor_prank: false` выключает шутку совсем.

## 3D-модель Мику (запасной вариант)

Модель в репозиторий не входит. Скрипт рассчитан на Blender-сцену Project SEKAI Miku, распакованную в
`assets/miku_model/` (`source/GameObject/GameObject.blend` + `textures/`). Для overlay её один раз
конвертирует скрипт (нужен Blender, проверено на 5.2):

```bash
.venv\Scripts\python tools\build_miku3d.py
```

Он: очищает сцену (остаются тело, лицо, аксессуары и два скелета), крепит голову к кости шеи,
создаёт анимации (idle, ходьба, прыжок, падение, сидение, сон, взмах, «тащат», погоня),
экспортирует `assets/miku3d/miku.glb`, конвертирует его встроенным в PySide6 `balsam` в Qt Quick 3D
(`assets/miku3d/qml/Miku.qml`) и подключает shape keys лица (моргание, глаза, эмоции, гласные рта).
Во время работы Blender не нужен. Если модели нет, показывается векторная заглушка
(`ui.avatar`: `auto` | `3d` | `placeholder`; размер — `ui.model_px`).

> Текстуры и модель — ассеты из игры Project SEKAI (SEGA / Colorful Palette, персонаж © Crypton
> Future Media). Подходят для личного локального использования; не публикуйте их вместе с проектом
> (`assets/` исключены в `.gitignore`).


## Что не входит в репозиторий

| Что | Где должно лежать | Почему не в репозитории |
|---|---|---|
| 2D-спрайты Мику | `assets/sprites/miku_sheet.png`, `miku_idle.gif` | сторонний фан-арт, лицензия неизвестна |
| 3D-модель и текстуры Мику | `assets/miku_model/` → после сборки `assets/miku3d/` | сторонние ассеты игры, распространять нельзя |
| Дообученная модель (GGUF / LoRA) | загружается в LM Studio | большие файлы; лицензия Gemma и происхождение данных |
| Датасеты обучения | `miku_data/*.jsonl` | не предназначены для публикации |
| Ваши данные: память, логи, токен, настройки | `data/`, `config/settings.json` | личные данные, создаются при первом запуске |
| Модели речи (faster-whisper, Silero) | `data/models/` | скачиваются автоматически при первом запуске |
| RVC-модель голоса Мику | в вашем Applio (`%LOCALAPPDATA%\Applio\data\runtime\logs\`) | ваш файл; голос персонажа — Crypton Future Media |

Без 3D-модели показывается векторная заглушка; без модели в LM Studio работают персонаж и память,
но не чат. Подойдёт любая загруженная в LM Studio модель с поддержкой tool calling — выберите её в
`lmstudio.model` или через `lmstudio.model_preference`.

## API (для своих клиентов)
