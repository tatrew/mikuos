# MikuOS: система 3D-анимации

Актуализация: 24 октября 2026. Движок остаётся PySide6 / Qt Quick 3D.
Python backend и его LLM-пайплайн сохранены. Unity/Godot не добавлялись.

## Ассеты и проверка исходника

- Исходник: `assets/miku_model/source/GameObject/GameObject.blend` (не изменён).
- Runtime: `assets/miku3d/miku.glb`, `assets/miku3d/qml/Miku.qml`, meshes/maps/animations.
- Сборка: `.venv\Scripts\python.exe tools\build_miku3d.py`.
- Аудит: Blender `-b <исходник> --python tools/audit_character.py`.
- Машиночитаемый результат: `data/validation/source-rig-audit.json`.

В исходнике 150 костей тела и 37 костей головы. Body: 4880 вершин, 72 vertex groups;
Face: 4126 вершин, 24 группы, 26 facial shape keys плюс Basis. У Body/Face нет
непривязанных вершин. У 36/13 вершин соответственно сумма весов отличается от единицы.
Acc: 489 вершин без весов; экспортёр сохраняет существующий способ жёсткого крепления
аксессуара к Head. Исходные масштабы не единичные, экспортёр нормализует общую высоту.
Исходных Actions и bone constraints не найдено. Есть цепочки волос/юбки, готовой физики нет.
Blender сообщает о трёх повреждённых orphan ShapeKey-блоках; используемые ключи Face доступны.
Исходный blend не пересохраняется, поэтому это предупреждение не скрыто «исправлением» файла.

## Путь кадра

`WindowTracker → SurfaceDetector → AvatarController → AnimationStateMachine → Pet3DWindow`.
Внутри Pet3DWindow: `ClipLibrary → PoseMixer → ограниченные добавочные движения → Qt joints`.

`tools/export_miku.py` создаёт и запекает 19 клипов в GLB. Это авторские базовые движения,
не mocap и не заявление о кинематографическом качестве. `PoseMixer` читает LINEAR/STEP
каналы GLB, применяет quaternion SLERP и 280-мс smoothstep crossfade. При прерывании
переход начинается от текущей показанной позы. Отсутствующие клипы вызывают ошибку,
а не незаметно заменяются idle. CUBICSPLINE/sparse animation accessors не поддерживаются.
Qt Timeline отключены через `externalAnimation`, поэтому второй писатель костей отсутствует.
Ключи лица не записываются клипами и принадлежат контроллерам выражений/голоса.

Ходьба использует запечённую двухзвенную IK. Длины сегментов вычисляются между началами
суставов: tails импортированного рига не соответствуют анатомической длине конечностей.
Опорная фаза линейная, перенос стопы — отдельная дуга. Скорость воспроизведения связана
с `walk_speed` и размером модели. Тест проверяет высоту/скорость опорной стопы в самом GLB.
Во время разворотов/crossfade полной runtime фиксации стоп пока нет.

## Состояния

| Состояние | Завершение / особенности |
|---|---|
| Idle, Walk, Run | локальное поведение; Walk/Run получают допустимую цель на опоре |
| Jump → Fall → Land | баллистика; Land 0,4 с, затем Idle |
| Sit → SittingIdle | посадка 0,6 с, затем покачивание ног |
| SittingIdle → StandUp → Idle | вставание 0,6 с; запрет прямого перехода в Walk |
| Wave, Happy, Surprised | однократные клипы, возврат в Idle |
| LookAround, Think, Sad | ограничены временем, возврат в Idle |
| Sleep | сон; пробуждение через StandUp |
| Drag, Chase, Look | сохранённые состояния desktop-клиента |

Команды во время падения/прыжка ждут приземления; последняя команда заменяет предыдущую.
Ожидание ограничено 15 секундами. Окно назначения перепроверяется после приземления.
Недоступная/слишком узкая/далёкая поверхность отвергается. Это прямые баллистические
прыжки, не поиск многошагового маршрута. Невидимые/свёрнутые/служебные и собственные
окна фильтрует WindowsBridge. Максимизированные окна участвуют в перекрытии нижних окон.
Видимая позиция сглаживается после изменения геометрии опоры; при закрытии опоры — падение.

## Процедурные слои

- Дыхание и небольшое движение головы находятся в idle-клипе.
- Моргание имеет случайный интервал 2,5–6 секунд.
- Глаза плавно следуют курсору; шея получает ограниченный добавочный поворот.
- `CursorInteractionController`: при расстоянии <70 px мягкая IK правой руки.
  Цель ограничена областью перед телом и 94% длины руки. Слой активен только в Idle/Look,
  не конфликтует с Walk, падением, посадкой и жестами. Проверен фактический Qt-кадр.
- `HairPhysicsController`: угловая пружина с подшагом не крупнее 1/120 с, damping и пределом
  10°. По два начальных сустава каждого хвостика и два корня юбки. Есть выключение/интенсивность.
  Это ограниченная вторичная динамика, **не полноценная коллизия с мешем тела**.

## Backend и эмоции

Новый API использует существующую защиту token/Host/Origin:

`POST /api/character/command`, заголовок `X-MikuOS-Token`:

```json
{"emotion":"happy","intensity":0.75,"animation":"wave","duration":2.5}
```

```json
{"action":"sit_on_window","target_window_id":12345}
```

Допустимы neutral, happy, excited, shy, curious, confused, surprised, sad, sleepy,
thoughtful. `EmotionController` смешивает доступные eye/mouth morphs и возвращает их
к нейтральным после duration. Некоторые эмоции отличаются слабо: модель не имеет отдельного
ключа для каждой эмоции. `animation` выбирает клип; `duration` относится к выражению лица.
Высокоуровневые действия также включают walk/run. Координаты и кости API не принимает.
Ответ `dispatched` означает отправку события, а не подтверждение достижения окна.
LLM не подключена к постоянному управлению движениями; backend может публиковать
`character_command` напрямую через существующий EventBus.

## Голос

`VoiceAnimationController` получает данные финального воспроизведения **после RVC**.
Текстовый bubble больше не выдаётся за lip sync. Аудиобэкенд в этом проекте не реализован.

`POST /api/character/voice` принимает последовательность:

```json
{"event":"start","stream_id":"utterance-42"}
{"event":"energy","stream_id":"utterance-42","rms":0.2}
{"event":"end","stream_id":"utterance-42"}
```

RMS 0..1 отправляет владелец playback по **проигрываемым**, не заранее синтезированным блокам,
примерно каждые 20–50 мс. Для локального playback есть `feed_pcm(samples, stream_id)`
с нормализованными float samples. Вызывать изменение Qt-объектов только из GUI-потока.
Пакеты другого/закрытого stream_id игнорируются. Без свежей энергии 300 мс рот закрывается,
через 2 с поток считается неактивным. Attack/release сглажены. Будущие фонемы можно сопоставить
существующим mouth_a/i/u/e/o; фонемный декодер пока отсутствует. Эмоции обновляются независимо.

## Производительность и настройки

В существующих настройках появился выбор FPS, обычного/экономного качества и физики волос.
Остальные параметры доступны в секции `ui` конфигурации:

| Ключ | По умолчанию |
|---|---:|
| fps | 30 |
| background_fps | 10 |
| quality | normal (или economy, без MSAA) |
| hair_physics / hair_intensity | true / 1.0 |
| idle_cooldown_s | 4 |
| walk_probability / jump_probability / sit_probability | 0.45 / 0.15 / 0.20 |

Оставшаяся вероятность — Idle/LookAround/Think/Wave. Значения вероятностей следует задавать
с суммой ≤1. После cooldown добавляется случайная задержка 0–4 с. Sleep/скрытый fullscreen
снижают частоту логики до background_fps; скрытое окно не читает framebuffer. Qt использует
PreciseTimer, активных TimelineAnimation нет. Неизменные суставы повторно не записываются.

Каждые 5 с журнал клиента получает FPS логики, RSS и process CPU. CPU psutil — процент одного
логического ядра, не всей машины. `gpu_ms: null` явно обозначает отсутствие GPU timestamp query.
Фактический изолированный замер: 30,3 FPS, RSS 254,7 МБ, CPU 17,1% одного ядра.
GPU отдельно по процессу и совместная нагрузка с LLM/RVC не измерены.

Реальное перемещение курсора по умолчанию запрещено. Сохранённая opt-in настройка ограничена
двухминутным сеансом, один сдвиг не чаще 15 секунд; аварийная остановка отключает её немедленно.
Для повторного сеанса требуется выключить и включить настройку. IK не перемещает указатель.

## Проверки и оставшиеся работы

Команды воспроизведения проверок приведены в TEST_REPORT.md. Кадры из Qt:
`data/validation/contact-sheet.png`, `cursor-ik.png`, `live-overlay.png`.

Не считать завершёнными:

1. Полные capsule/mesh collisions волос/юбки; устранение всех пересечений.
2. Runtime foot locking при поворотах, refined Run/Jump, отдельная фаза отталкивания с контактом стоп.
3. Mixed-DPI преобразования Win32 physical ↔ Qt logical и проверка на двух реальных мониторах.
4. Фонемы, реальный TTS/RVC playback и речевые жесты, синхронизированные с аудио.
5. Персональные GPU timing/VRAM, нагрузочный тест одновременно с LM Studio.
6. Многошаговый поиск маршрута, подтверждение результата высокоуровневых команд.
7. Экстренное восстановление персонажа далеко за экраном сохраняет старое перемещение в допустимую область.

Это работающая расширенная версия существующего клиента, но перечисленные ограничения
не позволяют объявить выполненной всю исходную спецификацию production-качества.
