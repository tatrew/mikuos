# Архитектура MikuOS

## Исходное состояние

В папке `miku/` до начала работы было: датасеты и LoRA-адаптеры для дообучения Gemma 4 E4B,
скрипт экспорта в GGUF, аудит лора (`miku_v5_repair/LORE.md`) и системный промпт
`miku_data/miku_persona_system_v4.txt` (из них в репозиторий входят только промпт и скрипт экспорта).
Приложения (backend, клиента, Unity-проекта) не было. Модель уже загружается в LM Studio
(дообученная Gemma 4 E4B, GGUF Q4_K_M). Поэтому:

- промпт используется как есть, из исходного файла (путь в настройках);
- правила лора соблюдены: лор хранится отдельно и помечен как художественный, вымышленные
  даты/концерты/родство не добавлялись;
- визуальный клиент создан с нуля.

## Выбор технологий

| Задача | Выбор | Почему |
|---|---|---|
| Язык | Python 3.12 (uv venv) | системный Python 3.14 повреждён; 3.12 — стабильные колёса PySide6/pywin32 |
| Backend | FastAPI + WebSocket, uvicorn | требование ТЗ; стриминг токенов, простой локальный API |
| LLM | LM Studio OpenAI-совместимый API через `httpx` | без SDK-зависимостей; нужен и нативный `/api/v0/models` (состояние загрузки) |
| Память | SQLite (WAL) + FTS5 | встроено в Python, полнотекстовый поиск без внешних сервисов |
| Windows | `ctypes` (user32/dwmapi/shcore/gdi32/shell32) + `comtypes` для UI Automation + `psutil` | реальные API без лишних слоёв; DWM-границы окон, per-monitor DPI v2 |
| Overlay | **PySide6 (Qt)** | Unity в проекте не было; Qt даёт per-pixel прозрачность, маску окна для click-through, трей, окна чата/настроек и WebSocket в одном процессе на том же языке, что backend (общий код WindowsBridge). Unity для 2D-плейсхолдера избыточен, а C#-мост добавил бы второй стек |

### Поток запроса

`User / Event → ContextBuilder → LM Studio → tool_calls → ToolRegistry (JSON Schema) →
PermissionManager → WindowsBridge → результат (role=tool) → LM Studio → ответ → проверка честности`.

1. **ContextBuilder** собирает: системный промпт (файл без изменений) + технические правила +
   список инструментов, доступных *сейчас* (запрещённые не показываются модели) + релевантная
   память (FTS5 c грубым русским стеммингом + 3 самых важных факта) + итоги прошлых разговоров +
   релевантный лор с пометкой «художественный» + разрешённые события (время, имя процесса
   активного окна — без заголовка) + последние сообщения, обрезанные по бюджету токенов
   (контекст берётся из `loaded_context_length` LM Studio). Полная история не отправляется.
   Если в базе нет ни памяти, ни прошлых разговоров, контекст прямо говорит об этом (якорь против
   выдуманных «общих воспоминаний»).
2. **AgentEngine** вызывает модель в стриминге с нативными tools. Ограничения: ≤5 раундов
   инструментов, после 2 ошибок подряд инструменты больше не предлагаются, после запроса
   подтверждения — тоже (модель не ищет обходных путей). Если модель *описала* инструмент словами,
   но не вызвала — до 2 служебных подсказок. JSON-fallback (`tool_mode`) принимает только объект
   `{"tool": <зарегистрированный>, "arguments": {...}}` без лишних ключей.
3. **Проверка честности**: если ответ содержит «открыла/создала/запустила…», а успешного
   side-effect-инструмента в ходе не было — ответ перегенерируется с указанием реальных статусов;
   если модель упорствует, добавляется пометка MikuOS.

### Инструменты и разрешения

Каждый `Tool`: имя, JSON Schema (`additionalProperties: false`), класс разрешения, тайм-аут
(выполнение в потоке), флаг «вывод содержит недоверенный текст». Каждое выполнение пишется в
`tool_audit`.

| Класс | По умолчанию | Инструменты |
|---|---|---|
| `observe_metadata` | allow | get_active_window, list_windows, get_window_geometry, get_cursor_position, get_user_idle_time, get_running_applications |
| `app_control` | allow | open_application (только `allowed_apps`, без аргументов командной строки, без shell), open_directory, open_file (исполняемые/скрипты/ярлыки заблокированы) |
| `window_control` | allow | focus/minimize/restore_window |
| `file_read` | allow | list_directory, read_text_file (только текстовые расширения) |
| `file_write` | ask | create_text_file (не перезаписывает), write_text_file (атомарно) |
| `observe_content` | ask | capture_window, read_window_elements (+ процесс должен быть в `content_allowed_processes`) |
| `ui_action` | ask | invoke_ui_element |
| `memory_write` | allow | remember_fact (чувствительное → очередь подтверждения) |
| `cursor_control` | deny | не предоставляется модели; используется только overlay при явном согласии |
| — | всегда | get_system_time, list_allowed_apps, search_memory |

Жёсткие правила поверх настроек:
- пути: `realpath` (симлинки, `..`) → обязаны лежать внутри разрешённых папок; UNC и NTFS ADS
  запрещены;
- **taint**: после того как в ходе был получен недоверенный текст (файл, заголовки окон, UI),
  любое действие с побочным эффектом, даже разрешённое, превращается в запрос подтверждения;
- автономные ходы (инициатива, события) не получают инструментов вообще; side-effect для них — deny;
- повтор одинакового действия: внутри хода не выполняется, между ходами — не чаще раза в 20 с;
- аварийная остановка: deny всего, кроме чтения собственного состояния; наблюдение и инициатива
  выключаются, `cursor_control` сбрасывается в `deny`.

Запрос «ask» хранится в PermissionManager (TTL 10 мин). Подтверждение из UI выполняет именно
сохранённый вызов, затем Мику отдельным ходом *без инструментов* сообщает реальный результат.

### Память

Таблицы: `conversations`, `messages`, `memories`, `character_lore`, `events`, `tool_audit`
(+ `pending_memories`, `embeddings`, `schema_migrations`). Внешние ключи (`ON DELETE CASCADE /
SET NULL`), индексы, FTS5-индексы с триггерами для `memories`, `messages`, `character_lore`.
Миграции версионированы и применяются в транзакции; при каждом запуске — онлайн-бэкап
(`sqlite3.backup`), хранится 10 последних.

| Тип | Где |
|---|---|
| Short-term | `messages` текущего разговора (в контекст — последние N в пределах бюджета) |
| Episodic | `memories(memory_type='episodic')` — итоги завершённых разговоров (LLM-суммаризация) |
| Semantic | `memories(memory_type='semantic')` — факты и предпочтения пользователя |
| Character | `character_lore` — только лор Мику |
| Activity | `events` (наблюдение без заголовков по умолчанию) + `memory_type='activity'` |

Авто-запоминание: явное «запомни, что…» / «забудь…» — детерминированно; плюс каждые 4 реплики
пользователя и при закрытии разговора — LLM-экстракция. Факт принимается, только если цитата из
ответа модели реально есть в словах пользователя (защита от выдумок). Дальше: чувствительное
(пароли, здоровье, адреса, телефоны, документы, финансы…) → `pending_memories` до явного
подтверждения; дубликат (сходство ≥ 0.85) → повышение уверенности; тот же `fact_key` с новым
содержанием → старый факт деактивируется (`superseded_by`). Разговор закрывается после 30 минут
тишины; незакрытый недавний разговор возобновляется после перезапуска.

`EmbeddingProvider` — интерфейс для будущего векторного поиска (таблица `embeddings` уже есть;
в LM Studio есть `nomic-embed-text`, но он не подключён — FTS5 достаточно для текущего объёма).

### Наблюдение и инициатива

ActivityObserver опрашивает раз в секунду только метаданные: смена активного окна (процесс),
запуск/закрытие приложений, перемещение окон, бездействие/возвращение, долгая работа в одной
программе, полноэкранный режим (`SHQueryUserNotificationState` + сравнение с монитором). Клавиши и
текст не собираются. Взаимодействия с персонажем приходят от overlay.

InitiativeEngine: режимы `chatty / normal / quiet / dnd` определяют допустимые триггеры;
cooldown по режиму (для клика по Мику ≤ 120 с), дневной лимит обращений к LLM считается по
`events` в SQLite (переживает перезапуск), подавление в полноэкранных приложениях, при аварийной
остановке и без LLM.

### Overlay

- `AnimationStateMachine`: idle, walk, jump, fall, sit, look, sleep, drag, chase, happy — с таблицей
  допустимых переходов.
- `SurfaceDetector`: «пол» = низ рабочей области каждого монитора; верхние кромки окон, обрезанные
  окнами выше по Z-порядку.
- `AvatarController`: гравитация, приземление, прогулки по поверхности, прыжки по баллистике на
  соседние окна, езда на перетаскиваемом окне (по дельте), падение при закрытии/сворачивании,
  взгляд и «попытка поймать» курсор (только анимация), сон при бездействии пользователя, респаун.
- `WindowTracker`: локальный опрос окон каждые 250 мс — без backend и LLM.
- `PetWindow`: frameless, translucent, always-on-top, Tool-окно; маска окна строится из альфа-канала
  кадра → клики мимо персонажа проходят насквозь. Qt работает в физических пикселях
  (`QT_ENABLE_HIGHDPI_SCALING=0`), как и Win32-слой, поэтому координаты разных мониторов и
  отрицательные координаты согласованы.
- **3D-аватар** (`pet3d_window.py`, `qml/Pet3D.qml`): модель Project SEKAI, которую дал пользователь,
  собирается `tools/build_miku3d.py` — Blender (фон) → glb со скелетом, 10 анимациями и
  морф-таргетами → `balsam` → Qt Quick 3D. Патч QML делает так, что играет ровно одна анимация
  (`animState`), а веса морфов привязаны к свойствам (моргание, сон, радость, взгляд, рот).
  Рисует `QQuickWidget` вне экрана (надёжная попиксельная прозрачность на Windows), ортографическая
  камера: 1 единица сцены = `model_px` пикселей, линия ног = y 0. Поворот к направлению движения
  сглаживается; при сидении модель опускается на высоту бёдер, ноги свисают с края. Маска кликов
  строится из альфа-канала кадра каждые 120 мс с расширением на 8 px. Анимации заданы
  процедурно в мировых осях (вращения пересчитываются в локальные оси каждой кости), поэтому
  скрипт не зависит от странных осей костей рипа.
- `PlaceholderRenderer` — векторная чиби-Мику, запасной вариант, если 3D-модель не собрана.
- Реальный сдвиг курсора — только если в backend `permissions.cursor_control = allow` (ставится
  в настройках после диалога согласия), не чаще раза в 15 с и никогда при аварийной остановке.

### Безопасность локального API

Токен на каждый запуск (`data/runtime/token`, права только владельцу через `icacls`); проверка
`Host` (защита от DNS-rebinding); запросы с `Origin` (браузеры) отклоняются; CORS-заголовки не
выдаются; OpenAPI/документация отключены; привязка только к localhost (иначе backend не стартует).
